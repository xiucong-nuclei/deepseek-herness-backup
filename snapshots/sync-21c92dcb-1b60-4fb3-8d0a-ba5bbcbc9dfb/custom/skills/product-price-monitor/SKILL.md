# 商品价格监控

监控一个具体可购买的商品，当归一化的含税总价或可用性条件达成时发出告警。显式处理变体、税费、费用、货币、库存、取消条款与重复告警。配置在前台一次性运行；周期性检查以 `cronjob` 定时触发的方式运行（`price-watch` 自动化蓝图为此提供脚手架）。

## 适用场景

- "这款笔记本低于 $1,000 时提醒我。"
- "盯一下这些航班，票价低于 $500 就提醒我。"
- "这家酒店有可退款房间时告诉我。"
- "跟踪门票/商品的可购状态。"
- 已有价格监控触发 cron 定时任务（第 4-6 步）。

不适用：一次性"这东西现在多少钱"查询（直接用 `web_search`/`web_extract`）。

## 流程——配置（前台，一次性）

### 1. 明确具体商品

记录来源 URL/提供商、可获取的商品/上架 ID、变体、数量、地点、日期、出行人/入住人、会员/登录假设、成色、卖家以及可接受的替代品。当两个变体不可能被混淆时即完成。

### 2. 明确告警条件

指定货币、含税总价还是税前价、最高价格、可用性/库存规则、运费、可退款性、舱位/房型/票种、冷却时间与通知目标。当合成示例都能得到确定性的告警判定时即完成。

### 3. 建立实时基线，然后安排定时任务

用 `web_extract` 或 `browser_navigate` 获取一个有边界的实时结果，记录抓取时间、来源价格、费用/税费、可用性与条款。在完成一次成功的前台抓取之前，不要安排定时任务。将监控契约（商品、条件、基线观测）写入 `~/.hermes/price-watches/<watch-slug>.json` 下的状态文件，然后创建任务：

```
cronjob(action="create",
        schedule="every 6h",
        prompt="Load the product-price-monitor skill and run the tick for the watch contract at ~/.hermes/price-watches/<watch-slug>.json.",
        deliver=<user's destination>)
```

选择尊重频率限制和站点条款的节奏。当基线精确匹配商品契约且任务已创建时即完成。

## 流程——定时触发（每次计划运行）

### 4. 抓取并归一化

重新抓取来源。只使用带时间戳的汇率换算货币，并保留来源货币。区分基础价格、强制费用、运费/税费、总额与可用性。排除易变的页面元数据。抓取失败意味着状态未知：报告或跳过，但绝不能用自己的错误页面覆盖上次的有效观测。当观测可与基线对比或明确标记为失败时即完成。

### 5. 比较并抑制重复告警

按需求对阈值突破、达标的可用性、明显更低的价格或价格回升发出告警。将上次有效观测与上次告警指纹存入状态文件。重放同一报价不得再次发送告警；遵守冷却时间。当告警判定对已存状态是确定性的时即完成。

### 6. 发送或保持静默

条件达成时，告警须包含：精确商品/变体、观测到的含税总价与来源货币、可用性/条款、阈值、抓取时间戳、来源链接以及重要的不确定性。绝不能声称库存已被保留。没有条件达成时保持静默——除非要求周期性"一切正常"通报，否则不发"仍在监控"之类的噪音。当状态文件反映本次运行结果时即完成。

## 易错点

- 拿基础票价去比含税总价阈值。
- 对错误的尺码、卖家、舱位、日期或房型条款发出告警。
- 用错误页面覆盖上次已知有效值。
- 轮询过于激进，触发封禁或违反站点条款。
- 在完成一次前台抓取之前就安排定时任务。

## 验证清单

- [ ] 监控契约锁定商品，两个变体不可能被混淆。
- [ ] 创建任何任务之前已完成一次前台抓取。
- [ ] 告警判定从状态文件确定性回放；重复告警被抑制。
- [ ] 失败的抓取从未替换上次已知有效状态。
- [ ] 告警包含含税总价、来源货币、时间戳与来源链接。
